# 16 · Deploy the demo in about 20 minutes

Database on **Supabase** (pgvector), API on **Render** (Docker, `render.yaml`), web on **Vercel** (`apps/web`), as decided
in CLAUDE.md. Synthetic data only: `DEMO_MODE=true` everywhere (docs/08 rule 1). You need your own accounts for the
three services; nothing here needs a credit card except an always-on Render instance for demo day.

## 1. Database: Supabase (5 min)
1. Create a project. Pick the region closest to the UAE that your plan offers (production moves to a UAE-hosted
   database, docs/07). Save the database password.
2. Database → Extensions → enable **vector**. (The schema also runs `CREATE EXTENSION IF NOT EXISTS vector`.)
3. Connect → copy the **Session pooler** connection string (port 5432), or the direct connection. Do **not** use the
   transaction pooler (port 6543): the API keeps prepared statements and runs `SET LOCAL ROLE` per request.
   It looks like `postgresql://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`.

## 2. API: Render (10 min)
1. New → **Blueprint** → connect this GitHub repository. Render reads `render.yaml` and creates `reprosense-api`.
2. Fill the two values it asks for:
   - `DATABASE_URL`: the Supabase string from step 1.
   - `ALLOWED_ORIGINS`: your Vercel URL (you can set it after step 3; the web app talks to the API through its own
     `/api` proxy, so this is defence in depth).
   - Optional: `ANTHROPIC_API_KEY` with `LLM_PROVIDER=auto` for written answers; leave `none` for the repeatable,
     extractive demo answers (they work offline and pass the 60-question eval).
3. Deploy. `DEMO_TOKEN_SECRET` and `NOTES_KEY` are generated by Render. On the first boot `SEED_IF_EMPTY=true` loads the
   synthetic data; the log shows `first boot: seeded {'personas': 8, ...}`. A restart never reseeds a database that
   already has the personas.
4. Check `https://<your-api>.onrender.com/readyz`: `"personas": 8`, `"kb_chunks": 93`, `"demo_mode": true`.
5. Free instances sleep after about 15 minutes idle (docs/08 rule 7). For the showcase, switch to a paid instance for the
   day or open `/healthz` 10 minutes before you present.

## 3. Web: Vercel (5 min)
1. Add New → Project → import this repository.
2. **Root Directory: `apps/web`**. Framework: Next.js (detected). Install and build commands: leave the defaults.
3. Environment variables (Production and Preview):
   - `API_URL` = `https://<your-api>.onrender.com` (required: the `/api/v1` proxy is written at build time).
   - `NEXT_PUBLIC_SITE_URL` = `https://<your-project>.vercel.app` (optional; Vercel's own domain is used otherwise).
4. Deploy, open the URL, go to **Demo people → Open Noura's record**.
5. Back on Render, set `ALLOWED_ORIGINS` to the Vercel URL if you skipped it.

## 4. Smoke test the live demo (2 min)
From your laptop, run the same e2e suite CI runs, against the live URLs (it resets the demo data first):
```bash
cd apps/web && PW_CHANNEL=chrome E2E_BASE_URL=https://<your-project>.vercel.app E2E_API_URL=https://<your-api>.onrender.com pnpm e2e
```

## 5. Demo day
- Reset the data on **Demo people → Reset demo data** after every rehearsal (docs/08 rule 8).
- Both URLs on venue Wi-Fi and a phone hotspot; Arabic and dark mode checked; PDF downloads (docs/08 checklist).
- Backup: the 2-minute screen recording on two laptops and a USB stick (docs/08 rule 10).

## What runs where
| Piece | Service | Config in the repo |
| --- | --- | --- |
| Database (Postgres 15+ with pgvector, forced RLS) | Supabase | `backend/app/db/schema.sql` (applied by the first boot) |
| API (FastAPI, WeasyPrint PDFs, rules, RAG) | Render, Docker | `backend/Dockerfile`, `render.yaml`, `.dockerignore` |
| Web (Next.js 15, EN/AR) | Vercel | `apps/web` (root directory), `API_URL` |
| CI (lint, types, unit, backend tests, e2e on the real stack) | GitHub Actions | `.github/workflows/ci.yml` |
